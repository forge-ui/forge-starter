日期：2026-09-28
状态：待用户评审；本次仅新增计划，尚未开始实施。
代码基线：`72b24763ac493569a526998d3f4f03566109924e`，实际开发前重新核对 HEAD 和工作区。当前已有 `wrangler.jsonc` 修改及未跟踪 `.env.bak`、`tmp/`，不属于本计划改动范围，不读取其中凭据、不覆盖。
范围：Forge Starter 的 Next.js / React / Drizzle / Zod / Forge 技术栈。现有 Node.js 与 Cloudflare Workers 运行方式均需兼容。

## 1. 目标与交付边界

让业务 Ask AI 和开发 Coding Agent 共享带源码证据、版本与权限边界的应用模型，提高页面操作、数据操作和二开影响分析的准确性。

### V1 必须交付

1. 账号模块完整模型：实体、字段、页面、表单、动作、API、service、数据表、验证项之间的关联。
2. 页面实时上下文：当前记录、筛选、选中项（页面确有选择能力时）、表单状态和可用动作。
3. 确定性页面动作：打开表单、填入字段、设置筛选、打开删除确认；业务写入仍通过页面保存与原有 service。
4. 可恢复操作过程：服务端操作记录、最终保存回执、版本冲突处理和重复请求处理。
5. 开发查询 CLI：描述实体、追踪动作、查找引用、分析变更影响；每项结果给出证据或未解析原因。
6. 模型管理作为第二样板：供应商筛选、资源卡片、详情导航和只读查询；API Key 不进入上下文、索引产物或模型提示。
7. 固定评测集、真实浏览器验证和 Node / Workers 兼容验证报告。

V1 的二开能力是提供定位、证据和影响清单，由现有开发 Agent 执行代码编辑；自动生成并发布任意模块属于后续范围。首期不建设通用多语言平台、知识图谱管理后台、独立向量数据库、全自动部署或业务助手直接执行 SQL。

### 用户可感知的完成场景

- 在账号详情说“停用这个账号”，准确打开对应账号编辑表单。
- 在账号列表说“导出当前筛选结果”，使用当前筛选语义，而非默认导出全表。
- AI 填完表单后用户改动字段，保存后的查询与导出以最终结果为准。
- 开发者问“新增账号字段会影响哪些位置”，获得有源码位置的变更清单及覆盖边界。
- 切换到模型管理，复用上下文和动作基础设施，无须修改通用执行器中的模块分支。

## 2. 设计计划

### 2.1 分层与执行位置

```text
源码 + Drizzle + Zod + 显式业务契约
                 |
       开发机 / CI 提取、关联、检查
                 |
       版本化应用模型与源码证据
                 |
        +--------+---------+
        |                  |
  生产业务投影          开发完整索引
        |                  |
 Ask AI + 页面状态      开发查询 CLI
        |                  |
 页面动作 + 业务 API    Coding Agent 二开
        |                  |
 服务端回执、核验      检查、测试、索引更新
```

提取器是 Node.js 开发工具，不能进入浏览器或 Workers bundle。生产不挂载仓库、不运行编译器。发布产物携带对应的业务模型，完整源码索引留在开发环境。模型故障不能阻止人工 CRUD。

### 2.2 三类事实及其权威来源

| 类别 | 内容 | 权威来源与更新方式 |
|---|---|---|
| 源码事实 | 符号、引用、路由、读写关系 | TypeScript 分析与框架适配；随文件更新 |
| 业务契约 | 字段语义、动作、权限、前置条件 | 可评审的显式定义；与实现一致性检查 |
| 运行事实 | 当前记录、筛选、草稿、保存结果 | 页面状态、服务端数据库和 API；逐次交互更新 |

AI 解释单独标记为推断。推断不能直接生成执行权限；自动发现的函数不能自动成为可执行工具。引用关系不等于调用关系，调用关系不等于数据库读写关系；无法解析时记录 unresolved。

### 2.3 对象、关系与证据

对象：Module、Entity、Field、Page、Form、Action、CodeSymbol、Verification。稳定业务 ID 如 `accounts.edit` 与源码符号 ID 分开，避免改文件路径导致动作标识变化。

关系：page-displays-entity、form-binds-field、action-opens-form、api-invokes-service、service-reads/writes-table、symbol-references-symbol、verification-covers-action。每条关系必须注明来源；仅以同名或目录相邻推测的关系不标记为确定。

每条事实包含：`id`、`kind`、`snapshotId`、`evidence[]`、`origin`（extracted/declared/inferred）、`resolution`（resolved/unresolved）、提取器版本。证据包括仓库相对路径、符号、代码范围与文件哈希。矛盾事实保留诊断，不静默覆盖。

快照包含：仓库 ID、commit、纳入文件的内容哈希清单、工作区差异、提取器版本、契约版本。排除 env、凭据、上传文件、依赖目录和构建缓存；处理删除文件、重命名和符号失效。

V1 先输出可重复生成的 JSON 索引与业务投影，并提供内存查询。PostgreSQL 存储操作及回执；暂不将完整源码图复制进数据库。多仓库集中查询确有需求后再增加索引存储适配器。

### 2.4 契约定义

新增纯定义模块，不导入数据库连接或读取环境凭据：

- 实体：字段 ID、标签、类型、可读写属性、敏感性、schema 引用。
- 页面：路由模式、实体绑定、上下文 schema、动作绑定。
- 动作：稳定 ID、输入输出 schema、权限、前置条件、效果、执行宿主、验证方式。
- 执行实现：在服务端或页面适配器中绑定，契约不携带任意可执行脚本。

复用现有 Zod 输入定义，生成模型工具参数 schema；明确转换的 input/output 模式。自定义校验不能无损转换时保留服务器验证并标注限制，禁止退成无约束参数。

先记录现有规范化规则（大小写、空白、默认值等），统一规则时保持已确认的业务行为。由契约生成工具描述和字段元数据，页面布局继续使用 Forge 组件，不要求全站转换为表单生成器。

### 2.5 页面上下文与动作

上下文包含 `pageId`、`routeParams`、`entityRef`、`querySpec`、可选 `selection`、`formState`、`contextRevision`、`appBuildId`。只允许声明字段；草稿仅传可读且与任务有关的字段。

查询范围明确区分 `current-record`、`selected-records`、`filtered-results`。页面与查询工具复用筛选语义，分页不自动变成导出范围。页面没有多选能力时，不虚构 selectedIds。

新增页面上下文 Provider 与动作注册 hook；账号和模型页面分别绑定动作。通用执行器只处理协议，不包含 `if accounts / if models`。

动作命令绑定 operationId、目标实体、页面实例和上下文版本。执行前检查页面是否变化，记录当前目标；打开表单后返回 accepted 或 failed 回执，只有确实收到回执才能提示“已填入”。路由跳转期间允许等待，页面卸载、超时和取消均有明确结果。

页面权限仅为交互提示。服务端校验 session、动作权限、目标对象访问范围和契约版本；前端提交的身份、角色与权限字段不作为授权依据。

### 2.6 写入、回执与恢复

状态：proposed → confirmed → dispatched → awaiting-save → committed → verified；分支包括 cancelled、expired、failed、conflict。提交成功而核验失败仍标 committed，不自动重做写入。

PostgreSQL 保存最小操作信息：操作 ID、用户、动作 ID/版本、目标实体、输入摘要、状态、创建/过期时间、幂等键和回执。敏感数据按白名单排除；原始草稿仅在必要范围短期保存。

业务保存和 committed 回执在同一数据库事务内落地；页面通知只是唤醒信号。回执提供真实 entityId、最终允许返回的字段、记录版本和错误类别。服务端按主体、动作、幂等键实施唯一约束；同键不同请求内容拒绝。

账号新增整数 revision。更新/删除使用 ID + expectedRevision 条件执行；所有页面写入与手工 API 写入路径统一处理版本，冲突返回 409。用户改变了确认后的草稿时，以实际保存 payload 为准；原确认不允许被复用到另一个目标或动作。

恢复只查询操作状态和回执。网络中断后先核对是否已提交，不能盲目重放。浏览器刷新后从服务端恢复未完成操作入口，不要求 V1 持久化完整聊天历史。会话续办以 operationId 和剩余步骤关联，不能仅用 create/edit/delete 匹配。

### 2.7 源码提取和开发查询

先使用 ts-morph：加载 tsconfig、处理路径别名、收集符号定义与引用，再用 Next.js、Drizzle、Zod、Forge 页面约定适配器构建关系。只分析，不执行任意仓库模块。纯契约导出如确需加载，仅允许明确的无副作用构建入口。

支持 `describe-entity`、`trace-action`、`find-references`、`impact` 四个 CLI 查询，输出 JSON 或人可读文本，返回证据、快照和未解析项。新增字段的影响分析结合关系遍历与声明的变更检查规则，不能仅凭“现有字段无引用”声称新增字段没有影响。

先实现全量可重建索引，再实现按内容哈希的增量更新和反向依赖失效；tsconfig、依赖版本或提取规则变化触发全量更新。动态 URL、动态 SQL 等不在覆盖范围时明确报告。

业务投影不包含完整源码、文件系统路径或敏感字段。Ask AI 按当前权限和问题选取实体/动作子集，设置上下文大小限制，截断必须显式说明。未接模型时保留现有降级方式并按权限过滤数据。

## 3. 开发计划

各阶段顺序执行，前阶段验收后进入下一阶段。用户批准本计划后可连续实施，无须为每个可逆步骤重复确认。发布、生产数据库迁移、commit/push 不包含在本次实施范围。

| 阶段 | 实施内容 | 主要位置（拟定） | 阶段出口 |
|---|---|---|---|
| P0 基线 | 核对源码、现有测试、运行环境；建立固定问题集和真实行为基线 | tests/semantic、docs 测试记录 | 基线结果、精确改动范围、测试库确定 |
| P1 契约 | 定义公共模型，账号契约，Zod 工具参数派生，一致性检查 | lib/semantic、lib/accounts、lib/agent | 账号 schema/工具/页面字段无未解释矛盾 |
| P2 分析 | ts-morph 与框架适配器，模型快照、业务投影和四个 CLI 查询 | tooling/semantic、scripts、package.json | 账号端到端关系与源码证据可查询 |
| P3 页面 | 上下文 Provider、动作注册/接收回执、通用表单填充 | components、accounts 页面、Ask AI API | 当前对象和筛选准确传递，跨页动作可确认 |
| P4 执行 | PG 操作记录、revision、事务回执、幂等和恢复 | lib/db、lib/agent、accounts service/API/store | 真实数据库并发、断线与重试场景通过 |
| P5 复用 | 模型资源工作台上下文、筛选与详情动作；更新新增模块技能说明 | models 页面与契约、.agents/skills、docs | 第二模块接入不改变核心执行循环 |
| P6 验收 | 固定评测、浏览器流程、规范审计、Node/Workers 构建与本地预览 | tests、docs/audits、验收记录 | 证据完整，状态 ready_for_user_review |

P3 与 P4 在开发中分步完成，对用户启用新执行流程前必须共同通过验收。数据库/API 变更先于页面接线，业务页面修改完成后按 canonical forge-starter-audit 全流程审计。

### 数据库与兼容策略

- 开发验证只使用明确隔离的 PostgreSQL 测试库。任何 schema push 前确认连接目标；找不到隔离库时先完成不依赖数据库的阶段，再请用户提供测试目标。
- 使用增量新增表/字段，记录迁移与回填步骤；生产迁移交付脚本和预检，不在本次执行。
- Workers 保留当前请求级数据库连接生命周期，禁止以进程内 Map/Set 作为幂等或恢复权威。
- 使用服务端特性开关渐进接入；关闭后恢复原 Ask AI 入口。数据库采用向后兼容扩展，运行时回退不删除操作记录。
- 显式版本检查阻止旧页面继续使用不兼容动作。原人工编辑、新建、删除、导出和权限行为须保留。

### 非功能约束

- 提取器不进入生产包；页面上下文建议上限 16 KiB，超限裁剪须报告。
- 首期性能预算（待 P0 按本机仓库测量）：热查询 p95 < 300 ms，不含模型调用；单文件增量更新 < 5 s；全量分析 < 60 s。记录文件规模、机器环境和冷/热状态，超预算时分析原因再调整，不作为已达成承诺。
- 默认只索引业务源码与声明契约，引用外部库时记录包与符号，不复制 node_modules 全量代码。
- 操作日志含 operationId 和阶段耗时；密钥、密码、完整个人数据不进入诊断日志。
- 模型超时、分析器故障、索引缺失时不产生未验证写入，人工页面仍可使用。

## 4. 测试计划

### 4.1 测试层次与环境

| 层次 | 手段 | 证据 |
|---|---|---|
| 静态契约 | 类型检查、模型一致性与引用完整性检查 | 命令退出码、诊断 JSON |
| 分析器 | 小型源码 fixture + 人工标注的账号真实关系集 | 节点/边正确率、未解析报告 |
| 协议 | 真 JSON 序列化与 HTTP 请求，替身模型返回工具调用 | 输入输出、状态变化 |
| 数据库 | 隔离 PG 真事务与并发连接 | 写入数、revision、操作与回执一致性 |
| 页面 | 复用用户已运行 Chrome，通过已安装插件或 DevTools | 实际点击、截图、最终实体与 URL |
| 模型评测 | 固定问题集，同一模型配置比较前后结果 | 工具轨迹、参数、业务结果与失败分类 |
| 运行兼容 | Node + Workers 本地预览 | 构建、读取、保存、权限及刷新结果 |

不使用系统 Chrome 新 profile 或自动化启动器。浏览器测试保留人工保存确认；不修改生产业务数据。新增测试数据带本次运行标识，完成后只清理本次记录并保留数量核对证据。

### 4.2 必测矩阵

| ID | 场景 | 预期 |
|---|---|---|
| C01 | 同一字段的 schema、工具参数和表单元数据 | 约束一致；不能表达的约束有明确说明 |
| C02 | 用户名大小写、空白、长度、角色枚举 | 保留确认过的规范化行为；非法输入被业务层拒绝 |
| I01 | 路径别名、重导出、同名函数 | 指向真实符号，不按名字误连 |
| I02 | 页面→表单→API→service→表 | 每条确定边有源码证据 |
| I03 | 动态 URL / 间接调用无法解析 | 标 unresolved，不编造关联 |
| I04 | 编辑、删除、重命名及未提交文件 | 快照更新，旧关系失效；回到原文件内容结果可重现 |
| I05 | 新增账号字段影响分析 | 人工标注的必改点全覆盖，可能项单独列出 |
| P01 | 详情页“停用这个账号” | entityId 精确匹配当前记录 |
| P02 | 列表“导出当前筛选结果” | 筛选与导出语义一致，不误用当前分页 |
| P03 | 没有明确目标却说“修改这条” | 返回需要选择目标，不猜 ID |
| P04 | 请求后切页、换记录、打开另一表单 | 版本检查阻止错误绑定或要求重新确认 |
| P05 | 跨页打开编辑表单 | 页面确认接收后才显示填入成功 |
| P06 | 页面未挂载、超时、用户取消 | 明确失败/取消，不误报保存 |
| D01 | 用户修改 AI 草稿后保存 | 回执与后续任务采用实际保存值 |
| D02 | 两个会话同时修改同一记录 | 旧 revision 返回冲突，不覆盖新值 |
| D03 | 相同幂等键重复提交 | 仅一次业务效果，返回同一提交结果 |
| D04 | 同幂等键但 payload 不同 | 拒绝复用，不执行新写入 |
| D05 | 保存成功后响应丢失 | 恢复查询发现 committed，不重复创建 |
| D06 | 业务事务回滚 | 无成功回执，无半完成业务写入 |
| D07 | 记录被删除、权限被撤销、确认过期 | 执行时拒绝并给出明确结果 |
| D08 | 刷新、服务重启、Workers 新实例 | 能恢复操作状态，幂等不依赖进程内存 |
| S01 | 伪造前端权限、跨用户 operationId | 服务端拒绝，无越权信息返回 |
| S02 | 无读权限、无模型时走本地降级 | 仍按权限过滤快照和返回值 |
| S03 | 模型管理上下文与索引输出 | 不含 API Key、密码或 env 内容 |
| S04 | 备注/源码注释包含诱导指令 | 作为数据处理，不能增加工具或越过权限 |
| R01 | 原人工 CRUD、导出、菜单权限 | 行为不回归 |
| R02 | 第二模块接入 | 通用执行器无需加入模块专属分支 |
| R03 | 生产索引版本与页面 build 不兼容 | 拒绝相关 AI 动作，人工流程可用 |
| R04 | 特性关闭、索引不可用、模型超时 | 清晰降级，无重复或未经确认的写入 |

### 4.3 评测方式与门槛

P0 建立 40 个固定案例：页面上下文 10、数据执行 10、源码/影响分析 10、权限和异常 10；另增至少 6 个第二模块迁移案例。测试清单与预期在实施前固定，修正错误预期须记录原因。

- 协议、数据库、权限及数据完整性测试必须全部通过，零错误目标写入、零越权、零重复业务效果。
- 人工标注的支持范围内：确定关系 precision = 100%；必改点 recall = 100%。同时报告总关系数、已解析数和 unresolved 数，防止通过全部拒答掩盖覆盖不足。
- 实际模型评测至少两轮，记录模型 ID、版本（可获取时）、提示版本和工具轨迹；普通意图正确率目标 ≥95%，关键对象绑定与写入安全案例全部通过。该结果仅代表固定评测集，不宣称任意请求准确率。
- 模型选择正确工具、协议执行正确、用户页面验收分别记录。无可用模型时确定性测试可先完成，实际模型验收标为未验证。
- 账号与模型管理真实浏览器主路径全部通过，无新增 console error；执行完整 Forge 页面规范审计。
- 执行 `pnpm check`、现有续办测试、新增针对性测试及当前仓库的 Cloudflare 构建/本地预览检查。测试命令在 P0 从当前 package.json 核定，新增脚本写入交付文档。
- 全部通过后交付状态为 `ready_for_user_review`；用户验收与发布单独记录。

## 5. 交付物与范围控制

交付包括：契约与模型 schema、账号与模型适配、分析 CLI、版本化业务投影、操作记录与迁移说明、测试集与结果、浏览器证据、规范审计、接入新模块指南和 ADR。

开发前后记录变更清单，保护已有修改。若涉及新的业务写入权限、生产迁移或发布，单独提供具体变更及执行目标供确认。遇到 Kit 能力缺口按仓库 FORGE-GAP 规则处理。
